# ADR-0022: Reconcile Redis toward Postgres with double-check + CAS; background loops separable from the API
Date: 2026-11-12 · Status: Accepted (guide ADR-020)
## Context
Inventory reserves with *Redis decrement → Postgres insert*. A crash between the two leaks stock (Redis too low); a Redis restart from an old snapshot makes it too high (oversell risk). Phase 1 only self-healed through reservation TTLs (known gap #6). Separately, every replica ran every background loop: you scale the API for web traffic but want one or two sweepers, and a loop crash must not take web requests with it.
## Decision
`ReconcilerService` (Inventory) compares each quiet counter (`stock:{variant}`, one `MGET` per 500 rows) with `qty_on_hand − qty_reserved` and corrects Redis toward Postgres, the accounting truth. Safety: skip rows changed in the last 60 s, re-read a suspect after a short pause, and heal only through a Lua **compare-and-set** (overwrite only if Redis still holds the drifted value we saw). Missing counters are cold caches, not drift. Every drift is logged (`STOCK DRIFT`), and > 0.5 % drifted logs an ERROR (the future alert). It runs hourly (`StockReconciler`) and on demand (`POST /api/v1/internal/inventory/reconcile`). All loops (`ReservationSweeper`, `StockReconciler`, `ExpireStaleOrdersWorker`, `DeliveryWorker`) register only when `Workers:Enabled` (default true) → in Kubernetes the same image runs as an **api** Deployment (`false`, many replicas) and a **worker** Deployment (`true`, 1 replica). MassTransit's outbox delivery stays in every API pod (lock-protected; events keep flowing while any pod is up).
## Alternatives
- Rebuild every counter from Postgres periodically (clobbers in-flight reservations → oversell) · heal silently (hides the bug or outage that caused drift) · distributed locks around reservations (slow hot path).
## Consequences
+ Drift is detected, explained in logs and healed without racing customers (tests in `tests/LankaMart.Inventory.Tests`). + Web scaling and loop scaling are independent. − A drift that appears and disappears within the quiet window is not seen (by design). − Alerting is a log line until Phase 6 monitoring.
