# ADR-0020: Transactional outbox + inbox via MassTransit EF, enforced by generic registration
Date: 2026-11-12 · Status: Accepted (guide ADR-018)
## Context
Phase 1 did "save to DB, then publish". A crash between the two left the database saying *paid / cancelled / registered* while nobody was told (profile never created, stock never released). RabbitMQ also delivers at-least-once, so consumers could apply a message twice.
## Decision
Every service uses `AddPlatformMessaging<TDbContext>(…)` (MassTransit **v8**, `MassTransit.EntityFrameworkCore`): **bus outbox** — `Publish` writes an `outbox_message` row that commits with `SaveChanges`, and a lock-protected delivery service sends it; **consumer outbox + inbox** — each consumer runs in one transaction with its own changes, its outgoing events and an `inbox_state` record, so a duplicate message id is skipped. The rule: *a `Publish` is durable only if a `SaveChanges` on the same `DbContext` follows it in the same transaction.* Code that mixes `ExecuteUpdate`/several `SaveChanges` with `Publish` uses `db.InTransactionAsync(…)`, which joins an existing transaction (consumers) or owns one. `OrderTransitions.TryAsync` and Inventory's confirm/release became transaction-aware for the same reason.
## Alternatives
- Hand-rolled outbox table + poller (more code to get right) · CDC/Debezium (heavy infra) · keep dual writes and rely on sweepers (they only paper over some cases).
## Consequences
+ Events are as durable as the data; the broker can be down for an hour and writes still succeed (the backlog drains on recovery); duplicate deliveries have one effect (tests in `tests/LankaMart.Orders.Tests`). The generic registration makes "messaging without an outbox database" a compile error. − Three extra tables per database; a forgotten `SaveChanges` after `Publish` silently drops the event (each publish site was reviewed: `grep -rn "\.Publish(" src/services`). − Redis side effects inside a consumer (Inventory add-back, cart restore) are not covered by the transaction — the stock reconciler (ADR-0022) heals the rare drift. − Outbox lag is checked by hand until Phase 6 alerts (known gap #14). − MassTransit v8 maintenance ends after 2026 (ADR-0003 decision stands).
